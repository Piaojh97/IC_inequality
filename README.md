# Older adults experience greater information narrowing on a short-video platform

Code, aggregate statistical data and model inputs for the manuscript. This package is prepared from the research files on 25 November 2026.

**No empirical person-level data are included.** There are no platform user identifiers, individual covariate tables, individual behavioural records, or individual longitudinal sequences. Saved simulation outcomes are also supplied as group summaries. The model generates synthetic agents in memory and writes aggregate results only.

The public workflow redraws the numerical results from aggregate inputs, exports the supplementary tables, and runs the information-dynamics model. Regression and mediation results can be inspected and plotted, but their estimation requires the unpublished person-level data. These two forms of reproduction are distinguished below.

## Quick start

Use Python 3.11. From this directory:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python code/verify_release.py
python code/reproduce.py
```

The last command prepares all main numerical panels, all supplementary figures, and the supplementary tables. It reads only files inside this package. Outputs are written to `outputs/figures/` and `outputs/tables/`; input data and reference figures are unchanged.

Individual entry points:

```sh
python code/reproduce.py --main 1
python code/reproduce.py --supplementary 12
python code/reproduce.py --tables
python code/export_tables.py
```

`export_tables.py` reconstructs the table CSV files from the included LaTeX table sources. It does not fit statistical models.

## Run the model

The runner uses the manuscript's population simulator. Its interface supplies aggregate topic inputs and draws behavioural profiles from the public age-group distributions. Individual simulated states remain in memory; only group statistics are saved.

The runner reads four input files from `data/model/inputs/`: `phi_video_v2.npy` (35-topic correlations), `item_popularity_video_v2.npy` (topic-level item frequencies), `user_alpha_mean_video_v3.npy` (35 topic-level preference parameters), and `age_behaviour_distribution.csv` (age-group profile frequencies). Despite its historical filename, `user_alpha_mean_video_v3.npy` contains one value per topic, not one row per user. `settings.json` documents the parameters used by the runner; it is not a separate runtime configuration file.

A small installation check:

```sh
python code/model/run.py --mode demo --users 12 --steps 200 --items 200
```

The short run checks execution only. Manuscript-scale runs use 5,000 interaction steps, 10,000 candidate items, ten recommendations per step and 100-step consumption windows:

```sh
# 100 calibrated behavioural combinations, 1,000 simulated users per cell
python code/model/run.py --mode grid --users 1000 --betas 7

# Full nine-level matching scan
python code/model/run.py --mode grid --users 1000 --betas 1,2,3,4,5,6,7,8,9

# A new 10,000-agent population sampled from the aggregate age distributions
python code/model/run.py --mode population --users 10000

# Eleven normalized doses for each of three oldest-group interventions
python code/model/run.py --mode interventions --users 1596
```

These are new seeded simulations, not a replay of the original per-agent assignments. The saved aggregate output files reproduce the historical numerical results. The full 900-cell scan is computationally substantial and is not run by the default figure-reproduction command. Settings and elapsed runtime are recorded alongside each new aggregate CSV in `outputs/simulation/`.

### Parameter definitions

- Exploration score `e` and exploitation score `x` take values 0–9.
- Baseline exploration intensity is `sigma = 0.018 + 0.0003458 * e`.
- Baseline exploitation intensity is `alpha = 5.6 + 0.1228 * x`.
- Baseline recommendation strength is `beta = 7`.
- The normalized intervention dose is `delta` in [0,1]. Applied separately: `beta = 7 - delta`; `alpha = alpha0 - 1.228 * delta`; `sigma = sigma0 + 0.003458 * delta`.
- A 30% adjustment means `delta = 0.3` on this normalized scale. It is not a 30% reduction or increase in the raw parameter's baseline value.
- The model uses stationary, final-window relative entropy for classification; the empirical analysis uses the minimum over follow-up. The common numerical criterion is approximately 0.719032.

## Reproduction notes

1. **No individual-level empirical re-estimation.** Public coefficients and standardized risks support checking and plotting the reported estimates. They do not contain the information needed to refit the individual-level regressions or recompute mediation standard errors.
2. **Distribution exports.** Empirical CDFs are exported on fixed grids; box plots use five group quantiles and contain no individual fliers. These preserve the displayed distributions at the documented resolution rather than publishing sorted individual values. Simulated distributions are aggregated in the same way.
3. **Legacy plotting details.** Figure 1b retains the criterion curve used in the plotting notebook, with the conditional mean minimum supplied in a separate column. Figure 1h,i retains the original age-axis transformation and coefficient-bound envelope. These are copied for traceability, not changed during packaging.
4. **Mean error bars.** The original notebooks used unseeded bootstrap mean intervals in some bar panels. Public mean-bar redraws use deterministic normal intervals from group SD and sample size. Original figure PDFs are retained for reference. Binomial risk intervals and saved regression intervals retain their stated methods.
5. **Calibration grid.** The stored 100-cell empirical grid and matching age distributions are retained together. Reconstructing deciles from rounded CSV values moves three users between tied cells in the author-side data; this package does not mix that reconstruction with the saved calibration grid.
6. **Pilot provenance.** Figure S3 uses values digitized from archived pilot-sample figures. It is not presented as a fresh reconstruction from individual hourly logs.
7. **Schematics and layouts.** Figure 2f,g and Supplementary Figure S10 are authored illustrations. The original vector figures and available Illustrator sources are included. The numerical redraws use portable fonts and are stored separately from the manuscript layouts.
8. **Historical beta=0 slice.** It is preserved in the saved grid because the original Figure 4 slices include it. The documented rerun scan covers beta=1,...,9, matching Supplementary Figure S16.

## Provenance and verification

`docs/data_provenance.json` records the source and meaning of each exported statistical file. `docs/code_provenance.json` records copied source files and the transformations applied to notebooks and the simulator. `docs/file_inventory.csv` and `docs/data_schema.json` specify each file's columns, row counts and aggregate grouping keys. `docs/reproduction_map.csv` distinguishes direct plotting inputs from supporting definitions and artwork. `SHA256SUMS.txt` records the release files.

`docs/release_audit.md` and `docs/release_audit.json` record the additional privacy, notebook-language and dependency review. The review includes generated outputs as well as release inputs. `code/verify_release.py` checks the reviewed schemas, notebook contents, English comments and documented code/data references, in addition to the numerical checks and file checksums. The release retains English topic labels only. The original-language label column is excluded from `topic_labels.csv`, and the verifier also scans all release text files for remaining Chinese characters.

`code/prepare_aggregates.py` is an optional author-side exporter. It requires an explicitly supplied private research directory and writes only aggregate tables. It is not needed to run any public reproduction command. No raw-data download is attempted by this package.

The existing model's MIT licence is retained under `LICENSES/model-MIT.txt`. No additional blanket licence is specified for the manuscript figures, aggregate statistical data or newly prepared wrapper code.
